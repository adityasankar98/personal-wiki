# Custom LLM Training

Custom LLM training involved measuring Karpathy's nanoGPT with a fixed 48-case language eval suite. The best model had 230k parameters, a 48-token context, and was trained for 38 seconds on synthetic sentences. The model continues sentences in the shapes it was shown and is not a chat assistant.

## Key points

### Building a Custom LLM — Class 4

Source: [[Custom LLM README|Custom LLM README § Building a Custom LLM — Class 4]], lines 3–21

- Training Karpathy's nanoGPT from scratch involved measuring it with a fixed 48-case language eval suite.
- The best model has 230k parameters, a 48-token context, and was trained for 38 seconds on synthetic sentences.
- The model continues sentences in the shapes it was shown and is not a chat assistant.

### 1. Headline results

Source: [[Custom LLM README#1. Headline results|Custom LLM README § 1. Headline results]], lines 25–97

- E2 left four cases failing, and targeted fixes in E3 resulted in a score worse than E2.
- At 2 layers, adding targeted teaching material did not raise the ceiling; it moved failures around.
- Vocabulary coverage is separate from learned pattern, which is the real measurement.

### 2. Where my predictions were wrong

Source: [[Custom LLM README#2. Where my predictions were wrong|Custom LLM README § 2. Where my predictions were wrong]], lines 101–136

- Coverage went to 48/48 exactly as predicted by pre-training verification.
- Scorable accuracy rose from 83.3% to 91.7%, contrary to the prediction.
- The model learned the `reference` case despite capacity concerns.

### 3. The experiments

Source: [[Custom LLM README#3. The experiments|Custom LLM README § 3. The experiments]], lines 142–218

- Experiment 1 generated 6,360 synthetic sentences from 8 domains times 6 nouns times 4 contexts times 4 adjectives times 8 frames plus 216 shopping sentences.
- Experiment 2 added extension material to the classroom sentences, resulting in 9,029 unique passages.
- Experiment 5 changed the model by increasing N_LAYER from 2 to 4 and running for 6,000 steps.

### 4. The extension corpus

Source: [[Custom LLM README#4. The extension corpus|Custom LLM README § 4. The extension corpus]], lines 222–294

- The extension corpus is generated by build_corpus.py.
- The corpus holds the latest version trained on by E4 and E5.
- Three corpus files changed after E2: the two-clause analogy frame (file 08), the missing 'happens after … the earlier meal is' combination (file 05), and 'the {plural} are …' (file 01).

### 5. Keeping the exam out of the textbook

Source: [[Custom LLM README#5. Keeping the exam out of the textbook|Custom LLM README § 5. Keeping the exam out of the textbook]], lines 298–325

- The eval suite is the exam and the corpus is the study material.
- The generator filters sentences containing an eval prompt, dropping 24 sentences.
- The loader would have refused files containing an eval prompt even across adjacent lines.

### 6. The failures, and what diagnosing them produced

Source: [[Custom LLM README#6. The failures, and what diagnosing them produced|Custom LLM README § 6. The failures, and what diagnosing them produced]], lines 331–429

- Lang_46 showed the model copying from a first clause due to a missing frame.
- Teaching frames fixed categories and analogies, but E3 scored lower due to lost cases.
- Lang_32 showed a conflict where the model ranked an answer but generated the negated word.

### 7. How it learns — traced through actual numbers

Source: [[Custom LLM README#7. How it learns — traced through actual numbers|Custom LLM README § 7. How it learns — traced through actual numbers]], lines 433–595

- Corpus is tokenized by lowercasing and splitting into whole words and punctuation.
- The model trains by predicting the successor token in a sequence.
- Loss values across different vocabularies are not comparable.
- Generation settings are the same throughout.
- Untrained output shows word salad without grammar or repeated structure.
- Final output shows fluent template sentences with a copy error discussed in section 6.

### 8. Chat interface

Source: [[Custom LLM README#8. Chat interface|Custom LLM README § 8. Chat interface]], lines 629–671

- The chat evidence used the experiment 5 model (llm_runs/20260922T021637_203555Z/model.pt: 4 layers, 230,848 parameters).
- Six real interactions were saved to results/chat-session2.json and results/chat-experiment5.json.
- Interface properties include a tiny language model, no conversation memory, and a 48 token context cap.

### 9. Reproducing this

Source: [[Custom LLM README#9. Reproducing this|Custom LLM README § 9. Reproducing this]], lines 675–750

- Setup creates a Python 3.12 virtual environment and installs requirements.txt plus numpy.
- Verification uses verify_corpus.py to check the corpus before training.
- Scoring rules state the model sees only the prompt, not choices or answer keys.

### 10. Limitation and next experiment

Source: [[Custom LLM README#10. Limitation and next experiment|Custom LLM README § 10. Limitation and next experiment]], lines 754–789

- The immediate cause of lang_46 was a missing frame, not capacity.
- Fixing the issue at two layers cost three cases elsewhere, indicating capacity was a ceiling.
- lang_39 cannot be fixed by teaching because its tested sentence is an eval prompt; the proposed next experiment tests whether a before/after rule taught on non-vehicle examples transfers.
